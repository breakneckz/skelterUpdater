# Skelter Arena — лаунчер и автообновление

Репозиторий обслуживает доставку обновлений игры **Skelter Arena**.

Схема простая:

- **`version.json`** в корне репозитория — манифест актуальной версии. Лаунчер читает его через
  `raw.githubusercontent.com`, поэтому никаких лимитов GitHub API и токенов у игрока не требуется.
- **GitHub Releases** — туда кладутся полный архив сборки, бинарные патчи с прошлых версий и сам лаунчер.
  Лимит 2 ГБ на файл, трафик не тарифицируется (в отличие от Git LFS с его 1 ГБ в месяц).
- **`launcher/`** — исходники `SkelterLauncher.exe`: проверка версии, скачивание патча или архива,
  сверка SHA-256, установка, самообновление, запуск.
- **`tools/hdiffpatch/`** — [HDiffPatch](https://github.com/sisong/HDiffPatch) 5.1.3 (MIT): `hdiffz.exe` строит
  патчи при публикации, `hpatchz.exe` вшит в лаунчер и накладывает их у игрока.

Сама сборка игры в git **не попадает** — только манифест, код лаунчера и инструменты.

## Как выпустить новую версию

Собери игру в Unity, затем из корня репозитория:

```powershell
.\tools\publish-release.ps1 -Version 1.0.34 -BuildDir "C:\Users\Dan\Desktop\Skelter" -Notes "Two new characters" -NotesRu "Два новых персонажа"
```

Скрипт сам сделает всё по порядку:

1. Запакует `BuildDir` в `dist/Skelter-Arena-1.0.34.zip`. В архив не попадают отладочная информация Burst
   и мусор, который оказывается в папке сборки, если запускать лаунчер прямо из неё
   (`SkelterLauncher*.exe`, `installed.json`, `updates`).
2. Построит патчи с трёх предыдущих версий, архивы которых лежат в `dist/` (см. ниже).
3. Соберёт `SkelterLauncher.exe`.
4. Создаст релиз `v1.0.34` и зальёт туда архив, патчи и лаунчер.
5. Перепишет `version.json` и запушит его.

Порядок важен: манифест уходит в репозиторий **после** того, как файлы уже лежат в релизе — иначе
лаунчеры увидят версию, которой ещё нет.

> **Не удаляй старые архивы из `dist/`.** Патч строится от архива прошлой версии — ровно того, что
> скачали игроки. Нет архива — нет патча, игроки этой версии скачают игру целиком.

### Патчи

Unity складывает почти весь контент в несколько больших файлов (`resources.assets.resS`, `sharedassets0.resource`…),
и они пересобираются при любом изменении. Поэтому «качать только изменённые файлы» почти ничего не даёт
(~426 из 535 МБ), а бинарный дифф — даёт: обновление 1.0.31 → 1.0.33 весит **33 МБ** вместо 535.

Патч `Skelter-Arena-A-to-B.hdiff` содержит только изменившиеся и новые файлы версии B, но дифф считается
относительно всей папки версии A — новые ассеты часто собраны из кусков старых файлов. Файлы, которых в B больше нет,
перечислены в `version.json` — лаунчер удалит их сам, `-CleanInstall` для этого не нужен.

Патч, который весит больше 80% полного архива, не публикуется — смысла нет. Построение занимает ~1 минуту
на каждую прошлую версию.

### Полезные флаги

| Флаг | Зачем |
|---|---|
| `-Notes` / `-NotesRu` | Что изменилось. Показывается в лаунчере после обновления: `-Notes` — на английском, `-NotesRu` — игрокам с русским интерфейсом (если пусто, им тоже покажется `-Notes`). |
| `-PatchDepth N` | Со скольких прошлых версий строить патчи (по умолчанию 3, `0` — без патчей). |
| `-CleanInstall` | Лаунчер сотрёт папку игры перед распаковкой **полного архива**. На патчи не влияет — они удаляют лишнее сами. |
| `-NoLauncher` | Не прикладывать `SkelterLauncher.exe` к релизу. Самообновление продолжит смотреть на лаунчер из прошлого релиза. |
| `-DryRun` | Спакует, построит патчи, посчитает хеши и перепишет `version.json` локально, но ничего не зальёт. |

`SkelterLauncher.exe` собирается и прикладывается к **каждому** релизу — иначе постоянная ссылка
`releases/latest/download/SkelterLauncher.exe` начнёт отдавать 404, как только выйдет релиз без него.
`-NoLauncher` эту защиту снимает, и скрипт об этом предупредит.

## Как это выглядит у игрока

Ссылка, которую раздаём игрокам — всегда одна и та же:

```
https://github.com/breakneckz/skelterUpdater/releases/latest/download/SkelterLauncher.exe
```

Игрок скачивает **только `SkelterLauncher.exe`** (~63 МБ, .NET внутри — ставить ничего не нужно)
и запускает его откуда угодно, хоть из «Загрузок». Дальше:

1. Лаунчер тянет `version.json`.
2. Если в манифесте лаунчер новее — обновляет сам себя и перезапускается.
3. Если игры ещё нет — показывает выбор папки («Обзор…») и галочку
   **«Создать ярлык игры на рабочем столе»** (включена по умолчанию), ждёт кнопку «УСТАНОВИТЬ».
4. Если игра есть и для её версии есть патч — качает только патч. Иначе — полный архив.
5. Сверяет SHA-256. Не совпал — перекачивает заново (одна попытка), потом показывает ошибку.
6. Устанавливает, создаёт ярлык и жмёт «ИГРАТЬ».

При следующих запусках обновления ставятся сами, без вопросов.

### Язык

Интерфейс по умолчанию на английском. Переключатель **EN / RU** — в правом верхнем углу окна,
меняет язык сразу и запоминается в `installed.json`. Все строки интерфейса — в [`launcher/Loc.cs`](launcher/Loc.cs),
английская и русская версии каждой строки лежат рядом.

### Как ставится патч

1. `hpatchz` (вшит в лаунчер, при первом патче достаётся в `%LocalAppData%\SkelterArena\tools`) собирает
   новые версии изменившихся файлов в `.update-staging` внутри папки игры. Игра в этот момент не тронута.
2. Каждый собранный файл сверяется с SHA-256 из манифеста.
3. Только после этого файлы переезжают на место, а выкинутые из сборки — удаляются.

Если патч не подошёл (игрок пропустил много версий, файлы игры изменены или повреждены — `hpatchz`
это видит), лаунчер пишет «Патч не подошёл — качаем версию целиком» и ставит полный архив.

### Самообновление лаунчера

В `version.json` лежит версия лаунчера из последнего релиза. Если она новее запущенной, лаунчер качает новый exe
рядом с собой, переименовывает себя в `.old` (запущенный exe нельзя перезаписать, но можно переименовать),
ставит новый на его место и перезапускается. `.old` удаляется при следующем старте.

Версия лаунчера — `<Version>` в [`launcher/SkelterLauncher.csproj`](launcher/SkelterLauncher.csproj).
**Поднимай её при каждом изменении лаунчера**, иначе игроки его не получат.

> Лаунчер 1.1 и более ранние версии самообновляться не умеют: копия в папке игры, на которую смотрит ярлык, у него защищена
> от перезаписи. Такие игроки продолжат получать обновления полным архивом — чтобы перейти на патчи, им нужно
> один раз скачать лаунчер заново по ссылке выше. Дальше он будет обновляться сам.

### Папка установки

- По умолчанию предлагается подпапка `Skelter Arena` рядом с лаунчером (или папка самого лаунчера,
  если он лежит рядом с `Skelter Arena.exe`).
- Если выбрать **непустую** папку (`D:\Games`, рабочий стол, корень диска), игра поставится в подпапку
  `Skelter Arena` внутри неё. Пустая папка, папка с именем `Skelter Arena` или папка, где игра уже
  стоит, используются как есть. Это заодно страховка от `cleanInstall`, который чистит папку целиком.
- Папки без прав на запись (`Program Files`) отклоняются сразу при выборе.
- Сменить папку можно только до установки. Уже установленную игру лаунчер не переносит.

### Ярлык на рабочем столе

- Ярлык `Skelter Arena.lnk` ведёт **на лаунчер**, а не на `Skelter Arena.exe`: иначе игрок запускал бы
  игру мимо обновлений. Иконка берётся из exe игры.
- Чтобы ярлык не сломался, когда игрок удалит лаунчер из «Загрузок», в папку игры кладётся копия
  `SkelterLauncher.exe`, и ярлык смотрит на неё.
- У установленной игры галочка показывает, есть ли ярлык сейчас: поставили — ярлык создан,
  сняли — удалён.

### Где хранится состояние

`%LocalAppData%\SkelterArena\`:

- `installed.json` — версия, путь к игре, выбор галочки, язык. Файл общий для всех копий лаунчера,
  поэтому копия в папке игры и исходный exe не качают игру заново друг за другом.
  Лаунчер 1.0 хранил `installed.json` рядом с собой — при первом запуске он подхватывается автоматически.
- `crash.log` — если лаунчер упал, текст ошибки дописывается сюда. Попроси игрока прислать этот файл.
- `tools\hpatchz-5.1.3.exe` — накладывает патчи.

### Что учтено

- **Докачка.** Оборвался интернет на 200-м мегабайте — при следующем запуске качает с того же места
  (`Range`-запрос), а не с нуля. Работает и для архива, и для патча, и для нового лаунчера.
- **Оборванная установка.** На время распаковки или замены файлов патчем в `installed.json` стоит флаг
  `updateInProgress`. Если процесс убили посередине, при следующем старте лаунчер это увидит и поставит версию
  полным архивом, а не запустит битую игру.
- **Офлайн.** Нет сети, но игра установлена — кнопка «ИГРАТЬ» работает.
- **Лаунчер не перезаписывает сам себя** (и свою копию в папке игры) при распаковке и патче, даже если попал в архив.
  `cleanInstall` не трогает кеш загрузок `updates/`, если лаунчер живёт в папке игры.
- **Zip slip.** Пути из архива и манифеста, ведущие за пределы папки установки, отклоняются.
- **Место на диске.** Проверяется до скачивания и до распаковки, причём для обновления поверх
  существующей установки считается только прирост размера, а не полный объём сборки.
- **Самообновление не зацикливается.** Перезапущенный лаунчер получает `--self-updated` и второй раз подряд
  себя не обновляет, даже если в манифесте ошибка.

## Формат version.json

```json
{
  "version": "1.0.34",
  "releaseDate": "2026-10-03",
  "url": "https://github.com/breakneckz/skelterUpdater/releases/download/v1.0.34/Skelter-Arena-1.0.34.zip",
  "sha256": "7d02b60c...",
  "size": 500572375,
  "executable": "Skelter Arena.exe",
  "cleanInstall": false,
  "notes": "Two new characters",
  "notesRu": "Два новых персонажа",
  "patches": [
    {
      "from": "1.0.33",
      "url": "https://github.com/breakneckz/skelterUpdater/releases/download/v1.0.34/Skelter-Arena-1.0.33-to-1.0.34.hdiff",
      "sha256": "…",
      "size": 34695659,
      "files": [{ "path": "Skelter Arena_Data/resources.assets", "sha256": "…", "size": 0 }],
      "remove": ["SkelterLauncher (1).exe"]
    }
  ],
  "launcher": {
    "version": "1.2.0",
    "url": "https://github.com/breakneckz/skelterUpdater/releases/download/v1.0.34/SkelterLauncher.exe",
    "sha256": "…",
    "size": 66149296
  }
}
```

| Поле | Смысл |
|---|---|
| `version` | Любая строка. Лаунчер сравнивает её с установленной **на неравенство** — можно и откатиться назад. |
| `url` | Прямая ссылка на полный архив в релизе. |
| `sha256` | Контрольная сумма архива. Пустая строка отключает проверку (не надо). |
| `size` | Размер в байтах. Нужен для прогресс-бара и докачки. |
| `executable` | Что запускать после установки. |
| `cleanInstall` | Очистить папку игры перед распаковкой полного архива. |
| `notes` / `notesRu` | Короткий текст, показывается в лаунчере после обновления (английский / русский). |
| `patches` | Патчи с прошлых версий. `from` — с какой версии; `files` — что получится после наложения (по этому списку лаунчер сверяет результат); `remove` — что удалить. Если файлы не менялись, а только удалялись, `url` пустой. |
| `launcher` | Последний лаунчер — для самообновления. Сравнивается как номер версии (`1.2.0 < 1.2.1`). |

Лаунчер 1.1 полей `notesRu`, `patches` и `launcher` не знает, пропускает их и качает полный архив, как раньше.

## Сборка лаунчера вручную

```powershell
dotnet publish launcher\SkelterLauncher.csproj -c Release -o dist\launcher
```

На выходе — один самодостаточный `SkelterLauncher.exe` (`win-x64`, .NET 8 внутри, `hpatchz.exe` вшит ресурсом).

Настройки, специфичные для игры, собраны в [`launcher/Config.cs`](launcher/Config.cs): адрес манифеста,
имя exe, папка установки по умолчанию, имя копии лаунчера и папки состояния.

### Проверка лаунчера без публикации

Если задать переменную окружения `SKELTER_LAUNCHER_DEV_DIR`, лаунчер работает в песочнице: манифест читает из
`<папка>\version.json` (локальный файл, ссылки внутри могут вести на `http://127.0.0.1:…`), а `installed.json`,
`crash.log` и ярлык кладёт в ту же папку. Настоящая установка, `%LocalAppData%` и рабочий стол не трогаются.

```powershell
$env:SKELTER_LAUNCHER_DEV_DIR = "C:\Temp\launcher-sandbox"
.\dist\launcher\SkelterLauncher.exe
```

## Предупреждение SmartScreen

`.exe` без сертификата подписи Windows встречает синим окном «Защитник Windows SmartScreen
предотвратил запуск». Это ожидаемо и лечится либо репутацией (накапливается по мере скачиваний),
либо покупкой code signing сертификата. Пока просто предупреди игроков: «Подробнее» → «Выполнить в любом случае».
Самообновление лаунчера этого окна не вызывает — файл скачивается самим лаунчером, а не браузером.
