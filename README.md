# Skelter Arena — лаунчер и автообновление

Репозиторий обслуживает доставку обновлений игры **Skelter Arena**.

Схема простая:

- **`version.json`** в корне репозитория — манифест актуальной версии. Лаунчер читает его через
  `raw.githubusercontent.com`, поэтому никаких лимитов GitHub API и токенов у игрока не требуется.
- **GitHub Releases** — туда кладётся сам архив сборки. Лимит 2 ГБ на файл, трафик не тарифицируется
  (в отличие от Git LFS с его 1 ГБ в месяц).
- **`launcher/`** — исходники `SkelterLauncher.exe`: проверка версии, скачивание, сверка SHA-256,
  распаковка поверх игры, запуск.

Сама сборка игры в git **не попадает** — только манифест и код лаунчера.

---

## Как выпустить новую версию

Собери игру в Unity, затем из корня репозитория:

```powershell
.\tools\publish-release.ps1 -Version 1.0.1 -BuildDir "C:\Users\Dan\Desktop\Skelter" -Notes "Что изменилось"
```

Скрипт сам сделает всё по порядку:

1. Запакует `BuildDir` в `dist/Skelter-Arena-1.0.1.zip` (отладочная информация Burst исключается).
2. Посчитает SHA-256 и размер.
3. Создаст релиз `v1.0.1` и зальёт архив как asset.
4. Перепишет `version.json` и запушит его.

Порядок важен: манифест уходит в репозиторий **после** того, как архив уже лежит в релизе — иначе
лаунчеры увидят версию, которой ещё нет.

### Полезные флаги

| Флаг | Зачем |
|---|---|
| `-CleanInstall` | Лаунчер сотрёт папку игры перед распаковкой. Нужен, когда из сборки **удалены** файлы (переименовал сцену, выкинул ассет) — иначе мусор от прошлой версии останется лежать. |
| `-NoLauncher` | Не прикладывать `SkelterLauncher.exe` к релизу. |
| `-DryRun` | Спакует и посчитает хеш, но ничего не зальёт. Для проверки. |

`SkelterLauncher.exe` собирается и прикладывается к **каждому** релизу — иначе постоянная ссылка
`releases/latest/download/SkelterLauncher.exe` начнёт отдавать 404, как только выйдет релиз без него.
`-NoLauncher` эту защиту снимает, и скрипт об этом предупредит.

## Как это выглядит у игрока

Ссылка, которую раздаём игрокам — всегда одна и та же:

```
https://github.com/breakneckz/skelterUpdater/releases/latest/download/SkelterLauncher.exe
```

Игрок скачивает **только `SkelterLauncher.exe`** (~63 МБ, .NET внутри — ставить ничего не нужно)
и запускает его откуда угодно, хоть из «Загрузок». Дальше:

1. Лаунчер тянет `version.json`.
2. Если игры ещё нет — показывает выбор папки («Обзор…») и галочку
   **«Создать ярлык игры на рабочем столе»** (включена по умолчанию), ждёт кнопку «УСТАНОВИТЬ».
3. Качает архив с прогрессом, скоростью и оценкой времени.
4. Сверяет SHA-256. Не совпал — перекачивает заново (одна попытка), потом показывает ошибку.
5. Распаковывает, создаёт ярлык и жмёт «ИГРАТЬ».

При следующих запусках обновления ставятся сами, без вопросов.

### Папка установки

- По умолчанию предлагается подпапка `Skelter Arena` рядом с лаунчером (или папка самого лаунчера,
  если он лежит рядом с `Skelter Arena.exe`).
- Если выбрать **непустую** папку (`D:\Games`, рабочий стол, корень диска), игра поставится в подпапку
  `Skelter Arena` внутри неё. Пустая папка, папка с именем `Skelter Arena` или папка, где игра уже
  стоит, используются как есть. Это заодно страховка от `cleanInstall`, который чистит папку целиком.
- Папки без прав на запись (`Program Files`) отклоняются сразу при выборе.
- Сменить папку можно только до установки. Уже установленную игру лаунчер не переносит.

### Ярлык на рабочем столе

- Ярлык `Skelter Arena.lnk` ведёт **на лаунчер**, а не на `Skelter Arena.exe`: иначе игрок запускал бы
  игру мимо обновлений. Иконка берётся из exe игры.
- Чтобы ярлык не сломался, когда игрок удалит лаунчер из «Загрузок», в папку игры кладётся копия
  `SkelterLauncher.exe`, и ярлык смотрит на неё.
- У установленной игры галочка показывает, есть ли ярлык сейчас: поставили — ярлык создан,
  сняли — удалён.

### Где хранится состояние

`%LocalAppData%\SkelterArena\installed.json` — версия, путь к игре, выбор галочки. Файл общий для всех
копий лаунчера, поэтому копия в папке игры и исходный exe не качают игру заново друг за другом.
Лаунчер 1.0 хранил `installed.json` рядом с собой — при первом запуске 1.1 он подхватывается автоматически.

### Что учтено

- **Докачка.** Оборвался интернет на 200-м мегабайте — при следующем запуске качает с того же места
  (`Range`-запрос), а не с нуля.
- **Оборванная установка.** На время распаковки в `installed.json` стоит флаг `updateInProgress`.
  Если процесс убили посередине, при следующем старте лаунчер это увидит и поставит версию заново,
  а не запустит битую игру.
- **Офлайн.** Нет сети, но игра установлена — кнопка «ИГРАТЬ» работает.
- **Лаунчер не перезаписывает сам себя** (и свою копию в папке игры) при распаковке, даже если попал в архив.
  `cleanInstall` не трогает кеш загрузок `updates/`, если лаунчер живёт в папке игры.
- **Zip slip.** Пути из архива, ведущие за пределы папки установки, отклоняются.
- **Место на диске.** Проверяется до скачивания и до распаковки, причём для обновления поверх
  существующей установки считается только прирост размера, а не полный объём сборки.

## Формат version.json

```json
{
  "version": "1.0.0",
  "releaseDate": "2026-09-25",
  "url": "https://github.com/breakneckz/skelterUpdater/releases/download/v1.0.0/Skelter-Arena-1.0.0.zip",
  "sha256": "697e1c5b...",
  "size": 282078707,
  "executable": "Skelter Arena.exe",
  "cleanInstall": false,
  "notes": "Первый релиз."
}
```

| Поле | Смысл |
|---|---|
| `version` | Любая строка. Лаунчер сравнивает её с установленной **на неравенство** — можно и откатиться назад. |
| `url` | Прямая ссылка на asset релиза. |
| `sha256` | Контрольная сумма архива. Пустая строка отключает проверку (не надо). |
| `size` | Размер в байтах. Нужен для прогресс-бара и докачки. |
| `executable` | Что запускать после установки. |
| `cleanInstall` | Очистить папку игры перед распаковкой. |
| `notes` | Короткий текст, показывается в лаунчере после обновления. |

## Сборка лаунчера вручную

```powershell
dotnet publish launcher\SkelterLauncher.csproj -c Release -o dist\launcher
```

На выходе — один самодостаточный `SkelterLauncher.exe` (`win-x64`, .NET 8 внутри).

Настройки, специфичные для игры, собраны в [`launcher/Config.cs`](launcher/Config.cs): адрес манифеста,
имя exe, папка установки по умолчанию, имя копии лаунчера и папки состояния.

## Предупреждение SmartScreen

`.exe` без сертификата подписи Windows встречает синим окном «Защитник Windows SmartScreen
предотвратил запуск». Это ожидаемо и лечится либо репутацией (накапливается по мере скачиваний),
либо покупкой code signing сертификата. Пока просто предупреди игроков: «Подробнее» → «Выполнить в любом случае».
